# Rules

## Project Rules

- Build only after hackathon start
- Keep a believable git history
- One task at a time
- One branch per task
- One reviewable diff per step
- No broad rewrites
- No scope expansion without approval
- No direct imports from `hecate-old`
- `hecate-old` is reference-only
- No Angular migration
- React is the chosen UI stack
- No mixed React/Angular setup
- No speculative abstractions
- No sponsor-driven feature creep
- Keep the MVP minimal and demo-first

## Agent Rules

Before coding, always provide:
1. task restatement
2. architecture intent
3. files impacted
4. minimal plan
5. assumptions and risks

After coding, always provide:
1. what was done
2. what was intentionally not done
3. what remains
4. suggested branch name
5. suggested commit message
6. temporary workaround introduced
7. cleanup needed later

## Submission Rules

- Document AI usage clearly
- Keep prompts/specs/planning artifacts in the repo when used
- Be explicit about reused vs new work
- Keep demo and repo coherent with the submission
